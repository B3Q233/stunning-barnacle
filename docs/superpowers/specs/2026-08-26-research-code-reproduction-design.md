# research-code-reproduction Skill 设计规格

## 1. 背景与目标

科研开源代码仓库通常只提供零散的 README、配置文件、脚本和论文链接。用户需要一份能够从环境准备一路执行到实验复现的可靠使用指南，而不是对 README 的简单转述。

本 Skill 的目标是：输入一个科研开源代码仓库，经过只读分析和必要的安全验证，输出一份中文、结构固定、证据可追溯的完整复现指南。Skill 不修改目标仓库，不替目标仓库新增脚本、配置或文档。

## 2. 范围

### 包含

- 分析本地目录、GitHub 地址或仓库压缩包中的科研代码。
- 识别仓库结构、入口脚本、依赖、数据集、权重、配置、训练、评估和推理流程。
- 将论文实验描述与源码中的可执行路径建立对应关系。
- 对安全、轻量、只读的环境和命令检查进行验证。
- 输出最小可运行流程、故障排查和复现检查清单。

### 不包含

- 不修改目标仓库的任何文件。
- 不执行训练、推理、批量评估、数据集下载或大文件下载。
- 不删除文件、不覆盖配置、不安装依赖、不创建虚拟环境。
- 不把 README 或论文中未被源码支持的内容写成确定事实。
- 不代替 `paper-pipeline`、`paper-understanding` 或 `paper-code-implementation` 完成论文提取、结构化理解或代码实现。

## 3. 输入与输出

### 输入

- 必需：目标科研代码仓库路径、GitHub URL 或压缩包路径。
- 可选：目标论文、指定实验编号、目标设备、已有环境信息、权重路径和期望输出格式。
- 当输入不完整时，优先从仓库自身推断；无法确认的部分必须标记不确定性，不得静默补全。

### 输出

输出固定包含以下章节：

1. 项目简介
2. 项目结构
3. 环境准备
4. 数据集准备
5. 预训练模型与权重
6. 配置说明
7. 训练
8. 测试与评估
9. 推理
10. 论文实验与源码映射
11. 常见问题
12. 最小可运行流程
13. 源码调用关系
14. 复现检查清单

每条关键命令都应注明来源、前置条件、是否验证以及验证限制。无法确认的内容使用 `⚠️ 未从源码确认`、`⚠️ 需要用户补充` 或 `推断：` 标记。

## 4. 核心原则

### 4.1 证据优先级

按以下顺序裁决冲突：

```text
源代码事实 > 配置文件 > 可执行命令验证 > README > 论文 > 推断
```

优先引用具体文件、函数、类、配置键和命令；对推断内容说明推断依据。

### 4.2 只读与验证边界

允许执行目录列表、文本搜索、版本查询、依赖导入检查、帮助命令和静态路径检查。禁止执行会训练模型、下载大量数据、修改环境或写入目标仓库的命令。对不能安全验证的命令，只做静态分析并说明原因。

### 4.3 事实与假设分离

将发现分为“源码确认”“配置确认”“文档声明”“命令验证”“合理推断”“无法确认”六类。任何涉及数据路径、权重命名、GPU 参数或实验结果的内容，若缺少源码或配置支持，必须显式标注。

## 5. 工作流

1. **仓库侦察**：确认输入类型、仓库根目录、版本信息、子模块、入口文件和主要语言。
2. **环境分析**：读取依赖文件、容器文件、安装脚本和版本约束，区分必需依赖与可选依赖。
3. **数据分析**：定位数据集加载器、默认数据根目录、预处理脚本、目录结构和数据格式。
4. **权重分析**：定位检查点加载逻辑、权重命名、下载地址、放置位置和结构校验。
5. **配置分析**：识别配置文件、命令行参数、默认值、设备设置、batch size、输出目录和 resume 逻辑。
6. **训练分析**：从入口脚本追踪到训练器、数据加载、优化器、保存逻辑和日志位置，给出静态确认的训练命令。
7. **评估与推理分析**：追踪测试、指标计算、单样本推理和批量推理路径，区分官方流程与推断流程。
8. **实验映射**：将论文中的表格、数据集、模型、指标和训练设置映射到源码入口及配置。
9. **故障排查**：针对 CUDA/PyTorch、路径、数据集、权重、OOM、权限和多卡/NCCL 等问题生成基于证据的排查步骤。
10. **文档组装**：按固定模板输出指南，并附最小可运行流程和复现检查清单。

## 6. 模块设计

### `SKILL.md`

负责触发描述、总流程、只读边界、证据优先级、决策规则、输出章节和模块加载顺序。保持简洁，将详细内容委托给 `workflow/`、`templates/` 和 `rules/`。

### `workflow/`

- `repository.md`：仓库结构、版本、入口、源码调用关系。
- `environment.md`：系统、Python、框架、CUDA、依赖和环境验证。
- `dataset.md`：数据来源、下载、目录、预处理和路径配置。
- `weights.md`：预训练权重、检查点、下载和加载验证。
- `config.md`：配置文件、参数覆盖、设备、输出和恢复训练。
- `training.md`：训练入口、阶段、命令、日志和 checkpoint。
- `inference.md`：测试、评估、单样本和批量推理。
- `troubleshooting.md`：常见错误的证据化排查顺序。

### `templates/`

- `usage-guide.md`：最终完整复现指南模板。
- `environment.md`：环境章节模板。
- `dataset.md`：数据章节模板。
- `troubleshooting.md`：故障章节模板。

### `rules/`

- `source-of-truth.md`：冲突裁决和引用文件证据规则。
- `command-validation.md`：允许、禁止和需用户确认的命令类别。
- `uncertainty.md`：不确定性标签、推断措辞和缺失信息处理。

### `agents/openai.yaml`

提供 Skill 列表的显示名称、简短描述和默认提示词，内容与 `SKILL.md` 的触发范围保持一致。

## 7. 验证与验收

- 使用 `skill-creator` 的 `quick_validate.py` 验证 frontmatter、名称和目录结构。
- 检查所有模块文件存在且互相引用路径有效。
- 检查描述以 `Use when...` 开头，且包含科研代码仓库、复现指南、环境、数据、权重、训练、评估、推理等触发关键词。
- 对至少一个本地科研仓库执行只读试运行，确认不会修改目标仓库。
- 验收输出章节完整，关键命令带证据状态，不确定内容带显式标记。
- 运行仓库规定的相关验证；若验证脚本需要网络、依赖或真实训练，则记录限制而不扩大执行范围。

## 8. 后续扩展

后续可增加不同框架的参考规则、命令抽取脚本、结构化 JSON 中间产物和针对特定论文仓库的适配器，但本次不实现这些扩展，以保持 Skill 的只读分析职责清晰。
