# 故障排查

## 原则

先定位证据，再给最小修复建议；不直接修改目标仓库。每个建议注明依据和副作用。

## 排查顺序

1. CUDA/PyTorch：核对 Python、torch、CUDA、驱动和设备可见性。
2. 路径：确认工作目录、配置中的相对路径、数据根目录和权重路径。
3. 数据集：确认目录树、文件名、划分、权限和预处理状态。
4. 权重：确认文件存在、格式、键名、模型结构和 checkpoint 版本。
5. OOM：记录 batch size、输入尺寸、显卡显存和是否多进程。
6. 多卡/NCCL：确认 GPU 数量、rank、端口、启动器和通信环境变量。
7. 权限/缓存：确认输出、临时目录和日志路径的写权限，但不替用户修改权限。

## 输出格式

对每个问题写：症状 → 可能原因 → 只读检查 → 保守处理 → 未确认项。没有源码依据的处理标记 `推断：`。

## 禁止

不建议删除缓存、覆盖权重、改源码、改配置、安装依赖或重跑完整实验作为第一步。
