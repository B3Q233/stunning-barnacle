# JSON Schemas

## meta.json (Step 1 extraction / Step 2 expanded)

```json
{
  "source": "PGD.md",
  "phase": "expanded",
  "expansion": {
    "max_expand_depth": 5,
    "stop_domains": ["high_school"],
    "scope": ["math_direct", "algorithm_direct", "model_structure_direct"]
  },
  "nodes": [
    {
      "id": "c_ridge",
      "name": "岭回归",
      "short": "岭回归",
      "kind": "concept",
      "section": "#5",
      "components": ["c_lsq", "c_reg"],
      "prerequisites": ["a_partial", "a_l2"],
      "proofAnchor": "#5",
      "description": "最小二乘 + ℓ2 惩罚",
      "provenance": "explicit",
      "proof_type": "derivation",
      "importance": null
    }
  ]
}
```

Rules:

- `kind` ∈ {`hs`, `atom`, `concept`, `method`, `contribution`}. It is the knowledge
  ROLE, not complexity:
  - `hs` 基础知识 (recursion stop; both lists empty; depth 0);
  - `atom` 不可拆分知识 (components empty);
  - `concept` 一般知识概念 (岭回归, 正则化, KKT, SVD);
  - `method` 论文/领域已有方法 (交替最小化, 核范数最小化, SVT, t 检验);
  - `contribution` 本文论文提出的创新知识/核心方法.
- `components` = 组成关系 (part-of, solid edge); `prerequisites` = 前置依赖
  (must learn first, dashed edge).
- DAG constraint applies to the UNION `components ∪ prerequisites` only; each list
  alone is not required to be acyclic.
- `proof_type` ∈ {`definition`, `derivation`, `empirical`}; default `derivation`.
- `provenance`: `"explicit"` (Step 1) or `"expanded"` (Step 2).
- `expansion` declares the Step 2 boundary (max depth, stop domains, allowed scopes).
- Old `parents` / `cost` / `complex` / `background` fields are deprecated; if present,
  `parents` is treated as `prerequisites`, `cost` is renamed to `dependency_depth`.

## all.json (Step 3, generated)

```json
{
  "meta": {
    "source": "PGD.md",
    "phase": "expanded",
    "expansion": {"max_expand_depth": 5, "stop_domains": ["high_school"]},
    "stats": {"hs": 17, "atom": 85, "concept": 22, "method": 3, "contribution": 8, "total": 135},
    "maxDepth": 13
  },
  "nodes": [
    {
      "id": "c_ridge",
      "name": "岭回归",
      "short": "岭回归",
      "kind": "concept",
      "section": "#5",
      "proofAnchor": "#5",
      "description": "最小二乘 + ℓ2 惩罚",
      "provenance": "explicit",
      "proof_type": "derivation",
      "components": ["c_lsq", "c_reg"],
      "prerequisites": ["a_partial", "a_l2"],
      "children_components": [],
      "children_prerequisites": ["p_altmin"],
      "dependency_depth": 6,
      "importance": 4,
      "learning_cost": null,
      "mastery": null,
      "effective_cost": 0.46,
      "proof_status": "unproven",
      "proof_deps": ["c_lsq", "c_reg", "a_partial", "a_l2"]
    }
  ],
  "edges": [
    {"from": "c_lsq", "to": "c_ridge", "type": "component"},
    {"from": "a_partial", "to": "c_ridge", "type": "prerequisite"}
  ],
  "topo": ["hs_func", "a_partial", "..."],
  "proof": {
    "initial": ["hs_func", "..."],
    "rule": "derivation/empirical nodes are provable iff every proof_deps id is proven; definition nodes are introduced once their referenced deps exist",
    "states": {"hs_func": "proven", "a_partial": "provable", "c_ridge": "unproven"}
  },
  "defaults": {
    "thresholdK": 0.5,
    "importanceThreshold": 6,
    "alpha": 0.5,
    "beta": 0.5,
    "learningCostMax": 10
  }
}
```

- `dependency_depth`: longest dependency chain over components ∪ prerequisites
  (hs = 0). It measures knowledge distance, NOT learning hours.
- `effective_cost` normalized to [0, 1]:
  `alpha * depth/maxDepth + beta * H/10` when H is a number, else `depth/maxDepth`.
- `proof_status`: `proven` / `provable` / `unproven`; `proof_type` explains HOW a node
  enters the proof domain (definition / derivation / empirical).

## user-state.json (Step 4, optional)

```json
{
  "mastery": {"a_partial": "weak", "c_kkt": "unknown"},
  "importance": {"p_attack": 9}
}
```

Overrides per node; unlisted values keep defaults.

## learning-cost.json (Step 4, exported)

all.json plus per-node user fields (`learning_cost`, `importance`, `mastery`) and the
recomputed normalized `effective_cost`.

## learning-path.json (Step 6, generated by plan_path.py)

```json
{
  "target": "p_sgld",
  "query": "SGLD 伪装攻击",
  "path": [
    {"id": "a_grad", "name": "梯度", "kind": "atom", "dependency_depth": 2,
     "effective_cost": 0.25, "importance": 3, "mastery": null}
  ],
  "excluded": {"hs": 17, "mastery_known": 0},
  "stats": {"path_length": 98, "max_depth": 12}
}
```

Order = topological order of the target's dependency closure (hs and mastery=known
nodes removed).

## Visualization actions (Step 5)

- Highlight（金色描边）: `kind == contribution` OR `importance >= k_imp`.
- Expand（红色脉冲 + “需学习”）: non-hs node with `effective_cost > k`
  (k in [0, 1]) OR `mastery ∈ {weak, unknown}`.
- The two actions are independent: high importance alone does not expand knowledge.
